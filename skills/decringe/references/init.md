# Init

Create usable audience and product records without a forced branding workshop.

Read [context](context.md). Inspect existing project guidance, public copy, relevant user journeys, and supplied customer evidence. Use a targeted search for current UI wording and action handlers if needed. Do not scan the entire application, start services, or browse private customer data merely to fill a template.

Use [AUDIENCE](../assets/templates/AUDIENCE.md) and [PRODUCT](../assets/templates/PRODUCT.md) as outlines. Replace their guidance with project-specific facts; remove irrelevant sections. Write the records in the selected project root or the existing `.decringe/` convention. Reuse a compatible `PRODUCT.md`. Edit existing records only as authorized by setup; preserve unrelated sections and provenance.

Populate what the conversation and artifacts establish. When audience motivation is uncertain, record a hypothesis with the evidence needed instead of inventing a persona. An empty field may read “Unknown”; it must not masquerade as a fact. Ask a focused question if choosing a primary audience is essential and cannot be inferred.

Write [VOICE](../assets/templates/VOICE.md) only when reusable voice decisions or approved examples exist. Write a surface [BRIEF](../assets/templates/BRIEF.md) only when a particular page or flow needs its own audience, goal, or action. Both are optional.

Report the saved paths and unresolved decisions that matter to the next writing task. Do not require approval again for facts already supplied. Do not rewrite the live copy unless the user asked for that too.
